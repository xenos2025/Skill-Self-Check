# Audience

## Who this is for (today)

| Audience | Why |
| --- | --- |
| Skill authors (Cursor / Claude Code / Codex) | Self-check a new `SKILL.md` before sharing |
| Small teams packaging internal skills | Same hard gates for everyone |
| Open-source skill maintainers | Scripted scores in PR review |
| Owners and operators reviewing AI workflows | Plain-language result, impact, and next action |
| Developers and security reviewers | Technical evidence, finding IDs, and limitations |
| AI beginners with mostly oral company processes | Turn one recurring job into a clear, measurable practice before delegating it |

## Who this is not for (today)

- People who only want a finished automation and do not want to clarify or own the workflow
- Teams needing a hosted SaaS skill marketplace
- Fully automated behavioral eval grids (roadmap)

## Who the workflow-readiness path is for

Product / ops people helping **foreign trade, factory, and ecommerce** teams:

- Map messy, oral work into an agent workflow
- Separate goals, steps, ownership, handoffs, measurable standards, and permissions
- Propose which skills to build or buy
- Keep proposals productized (acceptance, evidence, ship floor) — not slideware

The generic readiness gate is now stable in `skills/agent-work-readiness`.
Industry-specific interview and planning drafts remain in `exp/` until promoted.
